# 路线图（ROADMAP）

基于当前已实现的内核，后续演进方向。所有方向都**复用现有 `shared/` + `server/core/` 内核**，
无需重写规则逻辑。

---

## ✅ 已实现（MVP）

- [x] **4 / 5 / 6 人**三模式完整对局（发牌、亮主、扣底、叫朋友、出牌、收墩、结算、升级、换庄）
- [x] **Socket.IO 协议**：大厅 / 房间 / 游戏 / 回放全事件链（`docs/PROTOCOL.md`）
- [x] **房间系统**：座位 / 观战席 / 聊天 / 房主权限 / 自动开局 / GC
- [x] **棋牌状态机**：`PHASE` 七阶段流转，计时哨兵防卡局
- [x] **AI 托管**：启发式策略 + 掉线自动接管
- [x] **观战**：`seat<0` 只读席位，可选 `spectatorSeeAll`
- [x] **回放**：`Recorder` 逐帧录制，前端 `replay.js` 逐帧回放
- [x] **确定性随机**：`mulberry32(seed)`，可重现牌局
- [x] **headless 自测**：`test/simulate.js`（4/5/6 人 AI 对战全通过）+ `test/rules.test.js`（14 项规则单测通过）

---

## 🔜 近期（P1 — 体验与健壮性）

- [ ] **断线重连强化**：客户端主动 `reconnect` 后请求当前 `room:state` 增量补帧；
      对局中掉线前未完成的 `game:play` 队列恢复。
- [ ] **托管开关**：真人掉线时提供「等本人回来」vs「立即 AI 托管」选项（`Room.options.trustWhenOffline`）。
- [ ] **AI 策略升级**：
  - [ ] 记忆模块：记住已缺失的花色 / 已被毙的牌，决策不再「盲跟」；
  - [ ] 终局算分：手牌接近出完时按剩余分牌估算最优出法；
  - [ ] 难度档位：`easy/normal/hard` 对应随机扰动强度与搜索深度。
- [ ] **观战交互**：观战者可见全部手牌的开关 UI；观战聊天与「仅房主可见」提示。
- [ ] **回放增强**：进度条 / 倍速 / 跳到结算 / 导出 GIF 或分享链接。
- [ ] **房间口令 UI**：创建时输入密码、加入时校验提示（协议已支持 `password`）。

---

## 🚧 中期（P2 — 玩法扩展）

- [ ] **天地主 / 无主扩展**：当前 NT 逻辑已支持，补一个「强制无主」房间选项 + 天地主（大小王各为主）变体。
- [ ] **计分模式选项**：当前 `settleHand` 为「升 A 即胜」；可增加「固定局数 / 固定总分」结束条件。
- [ ] **2 副 vs 3 副自由选**：当前由人数决定，允许 4 人也用 3 副（调整 `MODE_CONFIG` + `kitty`）。
- [ ] **更多亮主姿势**：当前支持单 / 对级牌 + 王对；可扩展「级牌拖拉机亮主（更强）」。
- [ ] **记牌器**：副客户端可视辅助（仅展示已出大牌统计），作为观战/教学工具。

---

## 🌟 远期（P3 — 平台化）

- [ ] **匹配系统**：基于 ELO / 胜率的 `QUICK` 增强匹配（当前 `lobby:quick` 仅按模式补位）。
- [ ] **好友系统**：跨房间邀请、好友列表（需接入外部身份，见下方 Connector 建议）。
- [ ] **锦标赛**：多房间淘汰赛、自动编排、排行榜持久化（接数据库）。
- [ ] **可重放的教学模式**：AI 在关键墩给出「为什么这么出」的提示气泡，复用 `viewFor` 全视角。
- [ ] **WebRTC 观战推流**：低延迟观战（当前为事件流快照，已足够；高并发下可换 P2P）。
- [ ] **移动端适配**：`client/css` 响应式重写 + 触屏手牌拖拽。

## 🧩 与外部能力对接（Connector / Expert）

当前仓库为纯离线内核，下列能力若需要可接入对应 Connector（不写进内核）：

| 需求 | 建议 |
| ---- | ---- |
| 用户账号 / 跨设备进度 | 接 `github` / `wecom` / 自建 OAuth Connector |
| 排行榜持久化 | 接数据库类 Connector（如 CloudBase / TAPD 工单联动） |
| 聊天机器人 / 客服 | 接 `agent-mail` / 企业微信 |
| 规则法务咨询 | 接 `pkulaw` / `lexiang` 知识库 |
